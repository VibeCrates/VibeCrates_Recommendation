# 부정 표현 검색어 측정 (2026-10-28)

**목적:** 백엔드가 AstraGo(사전 → Gemma 3 4B → opus-mt)로 옮긴 뒤 "~하지 않은" 검색이 나빠졌는지 확인한다.
계기는 Gemma가 "무섭지 않은 영화"를 "a scary movie that won't be too frightening"으로 옮긴 사례 하나였다.

## 1. 번역 — `queries.csv`, `results.json`, `judgement.csv`

부정 표현 검색어 36개(영화·음악·책 각 12개)를 백엔드처럼 도메인을 지정해 두 서버의 `/recommend`에 보냈다.
Mac 서버는 사전 → opus-mt, AstraGo 서버는 사전 → Gemma → opus-mt로 번역한다. 모델 체크포인트는 같다.

번역문 표시는 판정기가 아니라 Claude가 읽고 했다.
O = 뜻이 맞음, △ = 부정은 남았지만 일부 뜻이 빠지거나 어색함, X = 부정이 사라졌거나 뜻이 틀림.

| | O | △ | X |
|---|---|---|---|
| Mac (opus-mt) | 11 | 13 | 12 |
| AstraGo (Gemma) | 30 | 2 | 4 |

- Gemma가 틀린 4개: 슬프지 않은 발라드 → "Sad ballads", 너무 빠르지 않은 댄스곡 → "fast dance songs"(부정 사라짐),
  야하지 않은 로맨스 영화 → "Romantic movies I haven't seen", 교훈적이지 않은 동화 → "Unwise fables"(단어 오역).
- 처음 계기가 된 "무섭지 않은 공포 영화" → "Scary movies that aren't frightening"은 △로 셌다. 부정은 남았지만 "scary"도 남았다.
- opus-mt는 "No, no, no, …", "You're not sad, Valad.", "Boring documentaries"처럼 부정이 사라지거나 문장이 깨진 경우가 많다.
- Gemma는 부정을 긍정 표현으로 바꿔 옮기는 경우가 많았다: 두껍지 않은 → "Thin", 어렵지 않은 → "Easy", 시끄럽지 않은 록 → "Quiet rock".
- 두 서버의 상위 10개는 중앙값 1개만 겹친다. 번역이 검색 결과를 거의 통째로 바꾼다.
- Gemma 응답은 모두 1초 제한 안(80~309ms)이라 opus-mt로 빠진 경우는 없다.

## 2. 번역이 맞을 때 모델이 부정을 반영하는가 — `neg_pos_pairs.csv`, `neg_pos_results.json`

번역이 맞게 된 영어 검색어 12개에 대해, 반대 뜻(긍정)과 수식어 없는 기본형을 만들어 Mac 서버에서 쿼리 벡터 코사인을 쟀다.
예: "Non-violent action movies" / "Violent action movies" / "Action movies".

| 비교 | 코사인 중앙값 |
|---|---|
| 부정 ↔ 반대 뜻 | 0.855 |
| 부정 ↔ 기본형 | 0.751 |
| 반대 뜻 ↔ 기본형 | 0.748 |

부정 검색어의 벡터가 기본형보다 반대 뜻 쪽에 더 가깝다. 즉 모델은 "non-violent"를 "violent"에 가깝게 읽는 것으로 보인다.
상위 10개 겹침은 어느 쌍이든 중앙값 1~2개라 이 축으로는 구별되지 않는다.
**결과에 실제로 반대 뜻의 작품이 섞이는지는 사람이 결과를 봐야 알 수 있고, 아직 보지 않았다.**

## 3. 116개로 다시 잰 부정 효과 — `triples.csv`, `triples_results.json`

2절의 12개는 "액션 영화는 원래 폭력적" 같은 장르 고유 특성이 섞여 있어 단편적이었다. 그래서 일반형·특성형·부정형을
116세트 만들었다. 장르와 무관한 특성 99세트(영화·음악·책 각 33)와 장르에 원래 붙은 특성 17세트(액션-폭력적, 공포-무서운 등)다.
부정형은 "Fantasy novels that are not scary"와 "Non-scary fantasy novels" 두 가지, 대조로 반대말형("Comforting fantasy novels")을 넣었다.
모두 영어로 Mac 서버 `/embeddings`에 넣었다(번역 없음).

**이동 비율** = 일반형 → 특성형 방향으로 부정형이 얼마나 움직였나. 1이면 특성형만큼, 0이면 제자리, 음수면 반대쪽.

| | 부정형 (that are not) | 부정형 (non-) | 반대말형 |
|---|---|---|---|
| 장르와 무관한 특성 (99) | +0.63 | +0.66 | +0.31 |
| 장르에 원래 붙은 특성 (17) | +0.62 | +0.71 | +0.52 |

- **116세트 모두** 부정형이 특성 쪽으로 움직였다(두 표현 모두 100%). 도메인별로도 +0.62~+0.74로 같다.
- 장르 고유 특성 여부와 관계없이 같은 크기다. "액션은 원래 폭력적"으로는 설명되지 않는다.
- 반대말형도 +0.31 움직인다. "sad"와 "happy"가 같은 감정 축을 공유하기 때문으로 보인다. 그래도 부정형은 그 두 배다.
- 부정형이 반대말형보다 특성형에 더 가까운 경우가 77%(that are not), 68%(non-)다.

**해석:** 모델은 "not sad"를 "sad"를 언급한 검색어로 읽고, 부정은 약하게만 반영한다.
부정을 반대말로 바꿔 넣으면 특성 쪽 끌림이 절반(+0.63 → +0.31)으로 준다. 번역 단계에서 부정을 긍정 표현으로 바꾸는 방식의 근거다.
이것은 벡터 기준이고, 검색 결과에 반대 뜻의 작품이 실제로 섞이는지는 사람이 결과를 봐야 확인된다.

## 4. 원인은 학습 전 CLIP이다

서비스 쿼리 인코더는 고정된 CLIP 텍스트 인코더(openai/clip-vit-large-patch14) 위에 학습한 MLP를 얹은 구조다.
같은 116세트를 학습 전 CLIP 출력에 넣어 이동 비율을 쟀다(장르와 무관한 특성 99세트, 중앙값).

| | 부정형 (that are not) | 부정형 (non-) | 반대말형 |
|---|---|---|---|
| CLIP pooler 출력 (MLP 입력) | +0.78 | +0.79 | +0.47 |
| CLIP 투영 출력 | +0.75 | +0.78 | +0.45 |
| 서비스 모델 (CLIP + MLP) | +0.63 | +0.66 | +0.31 |

CLIP부터 부정을 못 읽고(116세트 모두 특성 쪽), 우리 학습은 그것을 조금 줄였다.
3절 끝의 "학습 데이터에 부정이 없어서"라는 추정은 이 결과로 틀렸다.
