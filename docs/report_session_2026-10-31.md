### 2-2. 홈 추천 보드 제목 겹침 (10/23 ~ 10/24)

**문제:** 보드 4개의 제목을 보드마다 1등 후보로만 고르면 같은 제목이 반복됐다. 시뮬레이션 유저 중 같은 제목을 본 비율은 한 가지 취향 67%, 섞인 취향 51%였다.

**고친 방법:** 이미 고른 제목과 유사도가 0.8 이상인 후보를 건너뛴다. 기준값은 0.85 ~ 0.7을 비교해 골랐다.

| 기준 | 같은 제목 | 거의 같은 제목 쌍 | 제목과 보드 내용의 유사도 |
|---|---:|---:|---:|
| 현행 | 67% / 51% | 85% / 68% | 0.749 / 0.700 |
| 문자열만 비교 | 0% / 0% | 69% / 48% | 0.744 / 0.695 |
| **0.8** | **1% / 0%** | **2% / 0%** | **0.738 / 0.692** |

표의 각 칸은 한 가지 취향 / 섞인 취향 순서다.

- **문자열 비교만으로는 부족하다.** 같은 문자열은 사라지지만 "붉은 카지노 밤"과 "검붉은 카지노 밤들" 같은 쌍이 남는다.
- **0.8에서 남은 1%의 원인:** 후보가 전부 걸러지면 1등으로 돌아가는 처리 때문이다. 이 경우 "이미 고른 제목과 가장 덜 비슷한 후보"를 고르도록 바꿨다. 이 변경은 시뮬레이션으로 다시 확인하지 않았다.
- **수정안:** `~/Desktop/board_title_fix/`에 있고, 백엔드에 전달했다.
- **남는 한계:** 제목만 바꿨기 때문에 보드 4개의 내용 주제는 여전히 비슷할 수 있다.

### 2-5. 부정 표현 (10/28 ~ 10/29, `experiments/negation/`)

**계기:** AstraGo의 Gemma가 "무섭지 않은 영화"를 *a scary movie that won't be too frightening*으로 옮긴 사례였다.

1. **번역 (36개):**
   - 서비스 경로로 보냈을 때 뜻이 맞은 번역은 Gemma 30개, opus-mt 11개였다.
2. **번역기 단독 비교 (100개, `translation100/`):**
   - 부정 형태 8가지 × 3도메인을 사전을 거치지 않고 번역기에 직접 넣었다. 맞은 번역은 Gemma 82개, opus-mt 27개였다.
   - Gemma가 약한 형태는 짧은 부정 "안 ~"(6/10)과 "말고·빼고"(6/10)다.
   - Gemma가 틀린 12개 중 3개는 부정이 빠져 정반대 뜻이 됐다(예: 느리지 않은 발라드 → "Slow ballads").
   - 3개는 "빼고"를 포함으로 읽었다(예: 해리포터 말고 → "like Harry Potter").
3. **모델 (116세트, 영어로 직접 측정):**
   - **이동 비율:** 일반형("Fantasy novels")에서 특성형("Scary fantasy novels")으로 가는 방향을 1로 놓고, 부정형("…that are not scary")이 그 방향으로 얼마나 움직이는지 잰 값이다.
   - **결과:** 서비스 모델에서 중앙값 +0.63이고, 116세트 모두 특성 쪽으로 움직였다.
   - **원인:** 학습 전 CLIP 출력이 이미 +0.78이다. 고정된 CLIP 텍스트 인코더가 부정을 못 읽는 것이다.
   - **LoRA 체크포인트:** 예전에 학습한 CLIP LoRA 체크포인트도 +0.59로 같았다.
4. **연구 사례:**
   - 부정 데이터로 학습한 연구들(NegBench, NevIR, ExcluIR)은 일부 나아졌을 뿐, 해결하지 못했다.
   - 우리와 같은 구조, 즉 검색어와 문서를 따로 벡터로 만드는 bi-encoder는 학습 뒤에도 약했다.
   - 일반 검색 성능이 떨어진 사례도 보고됐다(NevIR의 MonoT5).
5. **보류 이유:**
   - 두 서버 로그의 한국어 검색어는 고유 기준 약 4만 개다. 그중 특성을 부정하는 검색은 사실상 0건이다.
   - 다룰 일이 생기면 학습보다 싼 방법부터 쓴다: 번역 단계에서 반대말로 바꾸기, "말고·빼고"를 백엔드 필터로 처리하기.

- **10/31:** 백엔드가 직접 구현하기로 해서, 수정안은 넘기지 않고 **필요한 로그 목록**을 알리기로 했다. 정리한 요구사항은 아래와 같다.
  - **노출 로그:** 검색 결과와 홈 추천 보드에 무엇을 어떤 순서로 보여 줬는지 남긴다. 원문 검색어, 모델 버전, 노출 id를 함께 남긴다.
  - **반응 로그:** 좋아요와 취소, 상세 보기, 보드 사진 저장을 노출 id와 함께 남긴다.
  - **보드 수정 전후:** 어느 작품을 빼고 어느 작품을 넣었는지 남긴다. 가장 확실한 부정과 정답 신호다.
  - **요청 id:** 백엔드와 AI 서버가 같은 요청 id를 남겨야 번역 로그와 이을 수 있다.
  - **노출 id 전달:** 좋아요는 이미 `likeToken`으로 보내므로, 백엔드가 토큰 안에 노출 id를 넣으면 프론트엔드 수정이 필요 없다.
  - **함께 정할 것:** 테스트 계정 구분, 보관 기간, 개인정보 처리방침.
- **바로잡은 것:** AI 서버 로그의 이상한 조합 검색어는 백엔드가 만든 것이 아니었다. 부하테스트 검색어(`load-test/lib/search-keywords.js`)였다.
