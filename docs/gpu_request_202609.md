# 슈퍼컴퓨팅 자원 신청 (2026-09) — 우리 팀 기재 내용과 근거

제출 양식은 학과에서 배포한 공용 시트이고, 우리(4팀 강현·권용준)는 네 칸을 채운다.
작성본은 `슈퍼컴퓨팅자원_컴공_캡스톤(한지형)_eclass_4팀작성.xlsx`이며, **리포에는
커밋하지 않는다** — 이 저장소가 공개이고 시트에 다른 팀 학생들의 이름이 들어 있다.

지난 학기(2026-03) 제출본과의 차이를 함께 적는다. 그때는 학습만 했고, 지금은 LLM 합성과
한국어 처리, 서빙까지 들어와 있어 네 칸 모두 바뀐다.

---

## 서버 배포시 사용할 이미지

```
pytorch/pytorch:2.11.0-cuda12.8-cudnn9-devel
```

지난 학기는 `pytorch/pytorch:2.2.1-cuda12.1-cudnn8-runtime`이었다. 지금 코드가 검증된
환경은 torch 2.11.0+cu128 / transformers 5.14.1(대여 서버 beast 기준)이라 그 계열로
맞춘다. 태그 존재는 Docker Hub에서 확인했다.

`runtime`이 아니라 `devel`을 고른 이유는 **nvcc가 필요할 수 있어서다.** 백로그 A5에서
배치를 키우려고 flash-attention을 검토하는데 소스 빌드가 필요하고, runtime 이미지에는
컴파일러가 없어 나중에 손을 못 댄다. 이미지가 커지는 대신 선택지를 남긴다.

**주의**: vLLM은 자체 torch 빌드를 가져와 학습용 환경과 충돌한다. 배포 후 venv를 둘로
나눠 쓴다(지금 beast도 `venv` / `venv_vllm` 구조다).

## 사용할 포트 번호

```
8000(FastAPI 추천 API), 8001(vLLM 서버), 8888(JupyterLab)
```

| 포트 | 무엇 | 지금 쓰는가 |
|---|---|---|
| 8000 | 추천 API(FastAPI). 검색어를 쿼리 벡터로 바꿔 백엔드에 준다 | 예 — 현재 맥북에서 이 포트로 돌고 있다 |
| 8001 | vLLM을 HTTP 서버(`vllm serve`)로 띄울 때 | **아니오 — 신청만 해 둔다** |
| 8888 | JupyterLab | 예 |

**8001은 지금 필요 없다.** 현재 `scripts/vllm_runner.py`는 vLLM을 파이썬 라이브러리로
직접 올려서 프롬프트 목록을 넣고 결과를 받는 방식이라 HTTP가 개입하지 않는다. 그래도
신청해 두는 이유는, 나중에 필요해졌을 때 신청서에 없는 포트를 여는 것이 번거로울 수
있고 미리 적어 두는 비용은 0이기 때문이다.

서버 모드가 실제로 필요해지는 경우는 이렇다.

- **추천 API가 요청 시점에 LLM을 부를 때.** 가장 현실적인 시나리오다. 지금 한국어
  검색어를 opus-mt-ko-en으로 번역하는데 poet 스타일에서 약하다(코사인 0.632, "하늘"이
  "Heaven"이 되는 식). 이걸 LLM 번역으로 바꾸면 사용자가 검색할 때마다 LLM을 불러야
  하고, FastAPI가 vLLM 서버에 요청하는 구조가 된다. 추천 이유 문구 생성이나 보드 제목
  자동 생성도 같은 형태다.
- **같은 모델을 반복해서 쓸 때.** Qwen2.5-VL-7B는 올리는 데만 몇 분이 걸린다. 28만 건
  배치 작업이면 로딩 비용이 묻히지만, 프롬프트를 고쳐 가며 200건씩 시험하는 단계에서는
  매번 다시 올린다.
- **팀원 둘이 같은 GPU를 쓸 때.** 각자 올리면 7B 모델이 메모리에 두 벌 올라간다.

반대급부도 분명하다. 서버 모드는 **아무도 안 쓰는 동안에도 GPU 메모리를 계속 잡는다.**
9/1에 beast에서 다른 사용자가 llama-server를 22시간째 띄워 25.8GB를 점유하는 바람에
우리 학습을 걸지 못했다. 배치 작업만 할 거라면 지금처럼 라이브러리 모드가 낫다.

## 사용할 모델

```
SBERT(all-mpnet-base-v2), CLIP(ViT-L/14), Qwen2.5-VL-7B-Instruct,
opus-mt-ko-en, paraphrase-multilingual-mpnet-base-v2
```

- **SBERT / CLIP** — 추천 모델의 두 인코더. 콘텐츠 텍스트는 SBERT, 쿼리와 이미지는 CLIP.
- **Qwen2.5-VL-7B-Instruct** — 세 가지 일을 한다. 아이템 설명 합성(190,739건), 학습
  라벨이 되는 쿼리 생성(92,447건), 평가 판정. 사람이 만든 검색 로그가 없으므로 이 모델의
  출력이 유일한 정답 데이터다.
- **opus-mt-ko-en** — 한국어 검색어 번역(`src/api/translation.py`). 없으면 한국어 검색이
  사실상 동작하지 않는다(쿼리 벡터 코사인 0.058).
- **paraphrase-multilingual-mpnet-base-v2** — 다국어 인코더 교체 후보(worklist 12-1).
  아직 검토 단계지만, 신청서에 없는 모델을 나중에 못 쓰게 될 수 있어 미리 적는다.

## GPU

```
A100 80GB 1장
```

지난 학기는 40GB 1장이었다. 올려 신청하는 근거가 셋이다.

1. **배치가 메모리에 막혀 있다.** 배치 256과 128이 모두 OOM이라 64로 학습 중이다.
   대조학습(InfoNCE)은 배치가 클수록 negative가 많아 유리하고, 이것이 백로그 A5로
   남아 있는 미해결 항목이다.
2. **Qwen2.5-VL-7B로 28만 건을 합성**하는 작업이 있어 추론 쪽 메모리도 크게 쓴다.
3. 학습과 합성을 한 장에서 번갈아 돌려야 해서 여유가 필요하다.

지난 학기 공문을 보면 팀마다 40GB와 80GB가 섞여 있었으므로 요청 자체는 가능해 보인다.
경쟁이 있으면 위 근거를 담당자에게 따로 설명해야 할 수 있다.
