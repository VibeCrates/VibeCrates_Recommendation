## 2. 무엇을 했나

### 2-1. 응답에 `domain` 추가 (`src/api/domain_intent.py`)

**목적:** 사용자가 "잔잔한 영화", "비 오는 날 듣기 좋은 노래"처럼 작품 종류를 밝혔으면 백엔드가
그 도메인으로 검색을 제한할 수 있게 한다. 백엔드는 검색어만 보내므로 서버가 읽어서 돌려준다.

- 값은 이름(`all`/`movie`/`music`/`book`)으로 정했다. 숫자는 순서 약속이 따로 필요하고 로그에서
  읽히지 않는다.
- **확실할 때만 제한한다.** 놓치면 다른 도메인이 섞일 뿐이지만, 잘못 제한하면 원하는 결과가
  사라진다. 그래서 작품 종류를 가리키는 명사(영화·노래·곡·앨범·책·소설·시집·에세이·OST 등)만
  단서로 보고, 장르(발라드·힙합 포함)와 동사(듣기 좋은, 읽을)는 단서로 쓰지 않는다.
- 비유와 수식어는 버린다: "영화 같은 노래" → music, "책 읽을 때 듣는 음악" → music,
  "songs from movies" → music. "영화나 책"처럼 둘 이상을 원하면 all.
- 로그 530종에서 45건을 제한했고(book 37, movie 6, music 2) 육안으로 모두 맞았다. all로 둔
  485건에는 도메인 명사가 없었다. 테스트 42건(`tests/test_domain_intent.py`).

### 2-2. 단어 조합형 검색어 번역 사전 (`src/api/translation.py`, `src/api/ko_en_dict.json`)

**목적:** 백엔드 로그의 실제 검색어는 "시집", "로파이 비 오는 날" 같은 단어 조합인데, 기존
번역기(opus-mt)가 여기서 무너졌다. 핵심어 손실률(검색어의 핵심 단어가 번역문에서 사라진
비율)이 33.0%였다 — 시집 → "Indulgent", 보사노바 → "Bosanoba".

- 어휘 468개를 Gemma 27B로 번역하고 사람이 검수했다(애매어 7개 제거, 8개 수정).
- 검색어를 사전 단위로 끝까지 쪼갤 수 있으면 사전 번역을 잇고, 하나라도 못 쪼개면 opus-mt.
- 로그 530종 핵심어 손실: opus-mt 33.0%, Gemma 27B 0.9%, **서빙(사전+opus) 0.0%**.
  다만 사전을 이 530종에서 만들었으므로 표본 안 수치다.

### 2-3. 문장형 검색어 — 사전은 안 된다

벤치마크 100문장을 어절로 나누면 695개이고 사전으로 풀리는 것은 33%였다. 100문장에서만 새
어휘가 347종 나왔다 — 동사 활용형(듣기·듣는·들으며), 말끝(추천해줘·ㅊㅊ), 고유명사(인터스텔라·
아이유)가 끝없이 나온다. 어휘를 다 채워도 단어를 이어 붙이면 부정("무섭지 않은 영화" →
"scary not movie"), 수식 관계, 비유("영화 같은 노래" → "movie songs")가 깨진다. 단어 조합형이
사전으로 풀린 것은 거기에 문법이 거의 없어서였다.

### 2-4. 문장형 번역기 품질 측정

**지표 — 벡터 일치도:** 기준 영어 문장과 번역문을 서빙 모델로 각각 인코딩한 쿼리 벡터의 코사인
유사도. 1에 가까울수록 번역을 거친 검색이 영어로 검색한 것과 같아진다. 0.70 미만은 "크게
놓침"으로 따로 센다.

**표본 140문장:** 평가 쿼리 40쌍(기준 영어는 사람이 쓴 원문) + 실사용형 100문장
(`data/translation/sentence_bench.tsv`, 요청·기분·장면·내용·음악·구어체·작품 언급. 기준 영어는
후보 출력을 보기 전에 작성).

| 번역기 | 벡터 일치도 | 크게 놓침 | 구어체 | 작품 언급 |
|---|---|---|---|---|
| Gemma 3 27B | **0.896** | 9 | 0.862 | 0.916 |
| Qwen2.5-VL 7B | 0.885 | 10 | 0.727 | 0.901 |
| Gemma 3 4B | 0.882 | **4** | 0.750 | 0.911 |
| Qwen3-4B (Mac 4비트) | 0.880 | 11 | 0.785 | 0.845 |
| Qwen2.5-3B | 0.861 | 12 | 0.709 | 0.815 |
| Qwen2.5-1.5B | 0.824 | 25 | 0.581 | 0.686 |
| **현재 서빙 (사전 → opus-mt)** | 0.780 | **37** | 0.600 | 0.575 |
| 번역 없음 | 0.059 | 140 | | |

- 현재 서빙의 평가 40쌍 점수 0.780은 9월 측정값과 같다 — 측정이 재현된다.
- 현재 서빙은 문장형 넷 중 하나꼴로 뜻을 크게 놓친다("다독여주는 느낌" → "poisoning me",
  "아이유 노래 같은 잔잔한 발라드" → "It's a calm ballad.").
- 4B급과 27B의 차이는 0.015(표준오차 0.008)로 작다. Qwen3-4B는 4비트로 줄여도 점수가 같다.
- 9월 판정 실험(검색 결과 관련성, 영어 0.766 / Qwen 0.730 / opus 0.667)도 같은 방향이다.
- 한계: 이 지표는 뜻이 같아도 표현이 다르면 깎는다("옳음과 다정함" → "truth or tenderness"가
  0.35). 큰 차이를 가르는 데는 믿을 만하나 0.01 단위 순위까지 믿을 지표는 아니다.
- Kakao kanana-1.5-2.1b는 beast의 transformers 5.x 설정 검증에 걸려 기동하지 못했다(미측정).

### 2-5. 문장형 번역 속도 측정

**Mac (MLX, Qwen3-4B 4비트, 한 문장씩)** — `scripts/bench_mlx_translation.py`

| 방법 | 중앙값 | 느린 쪽 10% | 벡터 일치도 |
|---|---|---|---|
| 기본 | 1.01초 | 1.47초 | 0.880 |
| **규칙 부분 KV 캐시 재사용** | **0.52초** | 0.72초 | 0.879 |
| + 짧은 구절 출력 | 0.49초 | 0.68초 | 0.873 |
| 0.6B 초안 모델 추측 디코딩 | 0.82초 | 1.10초 | 0.880 |
| 8건 묶음 생성 | 요청당 1.04초 | | |

출력은 평균 10토큰으로 짧아서 시간 대부분이 프롬프트 읽기다. 매번 같은 규칙 부분을 한 번만
계산해 두면 절반이 된다. 나머지 방법은 효과가 없거나 오히려 느렸다. 서버가 요청을 하나씩
처리하므로 문장형 20건이 몰리면 마지막 요청은 약 10초를 기다린다.

**beast GPU (RTX 5090, vLLM)** — `scripts/bench_gpu_translation.py`

| 모델 | 한 문장 중앙값 | 느린 쪽 10% | 20건 동시 전체 | 벡터 일치도 |
|---|---|---|---|---|
| Qwen3-4B | **0.067초** | 0.091초 | 0.13초 | 0.880 |
| Gemma 3 4B | **0.066초** | 0.097초 | 0.13초 | 0.882 |
| Gemma 3 27B (4비트) | 0.150초 | 0.198초 | 0.28초 | 0.895 |

Mac → beast 왕복은 약 9ms(ping). GPU면 4B가 Mac 대비 약 8배 빠르고, 동시 요청을 묶어
처리하므로 몰려도 줄을 서지 않는다.

## 3. 남은 것

1. **문장형 번역 배치 결정 — beast GPU 상시 사용 확인이 먼저.**
   - 권장 구성: 사전 → 저장된 번역 → beast GPU 4B 번역(제한 시간 0.5초) → 실패 시 Mac opus-mt.
   - 걸림돌: beast GPU는 다른 사용자와 공유한다(오늘 다른 작업이 최대 27GB 점유). 상시 6~8GB
     점유는 대여 측 양해가 필요하다. 접속 경로가 SSH뿐이라 터널 자동 복구가 필요하고, 10/1처럼
     예고 없는 환경 변경 전례가 있다.
   - beast를 못 쓰면: Mac에서 Qwen3-4B 4비트(KV 캐시 재사용, 0.5초) + 번역 저장 + 백엔드
     타임아웃 5초 이상 요청.
2. **백엔드 공지** — `domain` 필드와 번역 변경. 문장형 대응이 정해진 뒤 한꺼번에 알린다.
3. 비교 시트 `experiments/compare_titledrop_20261009.numbers`(120쌍) 라벨링 → 집계·커밋.
4. 도메인 쏠림 보정(점수 보정 vs cap5_guard), 학습 쿼리 벡터 번들(1.68GB) 전달 방법.

- 서빙 venv에 MLX(`mlx` 0.32.3, `mlx-metal`, `mlx-lm` 0.32.0)를 **의존성 없이(`--no-deps`)** 설치했다.

  **Mac 남은 디스크 3.5GB.**

  kanana 2.1B가 추가됐다.
