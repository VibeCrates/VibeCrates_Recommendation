# 실험 보고 — 쌍대 판정기의 어휘 오도 검증 (2026-10-08 ~ 10-09)

대상: `docs/worklist_2026-09-03.md` 1-3(사람 라벨)과, 그 결과에 달린 4-1(하드 네거티브)의
평가 방법. 판정기를 사람 라벨로 검증하고, 불합격 후 모델 교체·프롬프트 변형까지 시험한
기록이다. 각 수치가 **무엇을 어떤 방법으로 센 것인지**를 같은 자리에 적는다.

---

## 0. 한 줄 요약

쌍대 판정기는 **검색어와 단어가 겹치는 후보가 오답일 때 그 오답을 고른다.** 사람이
두 번 같은 답을 낸 그런 쌍 29개에서 현재 판정기(Qwen2.5-VL-7B)는 54.5%, Gemma 3 27B는
36.0%만 사람과 같았다(합격선 75%). 추론을 시키거나 예시를 보여 줘도 나아지지 않았다.
**로컬 판정기로는 어휘 지름길을 겨냥한 실험(4-1 등)을 평가할 수 없다.** 판정기는
어휘 축과 무관한 실험에만 쓰고, 4-1은 사람이 직접 평가한다.

---

## 1. 배경 — 무엇을 왜 시험했는가

4-1(하드 네거티브)은 "제목만 겹치고 뜻은 다른" 오답을 학습 배치에 넣어, 모델이 단어
겹침만 보고 고르는 지름길을 직접 벌주는 실험이다. 이것이 성공했는지 보려면 저울인
판정기가 바로 그 상황 — **단어 겹침이 오답 쪽을 가리킬 때** — 에서 정답을 골라야 한다.

9/9 시점에 확인된 것은 판정기가 어휘 단서가 없을 때(92.6%)와 양쪽이 비슷하게 겹칠 때
(100%) 사람과 맞는다는 것뿐이었다. 어휘가 반대 방향을 가리키는 쌍은 6월 라벨에 2개뿐이라
알 수 없었다. 그래서 그런 쌍을 표적으로 한 라벨 시트를 만들었다(`build_label_sheet.py`).

판정기가 이 칸에서 틀린다면, 4-1이 성공할수록 점수가 내려가는 저울이 된다.

## 2. 시험 설계

### 2-1. 라벨 시트 — 쌍을 어떻게 만들었나

같은 쿼리의 검색 결과에서 (가) 판정기가 보는 본문(제목을 가림)에 쿼리의 내용어가 1개
이상 겹치는 아이템과 (나) 하나도 겹치지 않는 아이템을 짝짓는다. 좌우는 무작위로 섞고,
어느 쪽이 겹치는지는 정답지(`_key.csv`)에만 둔다. **쌍을 고르는 데 판정기를 쓰지 않는다**
— 판정기가 헷갈리는 쌍을 골라 판정기를 시험하면 순환이 된다.

사람(라벨러 1인)이 쿼리에 더 맞는 쪽을 1 또는 2로 고르고, 애매하면 비워 둔다.

### 2-2. 순방향 쌍과 역방향 쌍

- **순방향 쌍**: 사람이 단어가 겹치는 쪽을 고른 쌍. 판정기가 내용을 봤든 단어만 봤든
  같은 답이 나오므로, 여기서 맞히는 것은 판정기를 믿을 근거가 되지 않는다.
- **역방향 쌍**: 사람이 단어가 겹치지 않는 쪽을 고른 쌍. 내용으로 판단하는 판정기와 단어로
  판단하는 판정기가 갈리는 유일한 곳이다. **이 시험의 핵심 지표는 역방향 정확도다.**

역방향 쌍은 사람의 선택으로 정해지므로, 라벨을 매기기 전에는 어느 쌍이 역방향인지 모른다.

### 2-3. 지표

- **정확도**: 판정기가 사람과 같은 후보를 고른 비율. 판정기에게 후보 순서를 바꿔 두 번
  묻고, **두 번 모두 같은 후보를 고른 쌍만** 판정 가능으로 센다(위치 편향 제거). 분모는
  판정 가능한 쌍 수다.
- **양방향 일관성**: 전체 쌍 중 두 번 같은 후보를 고른 비율. 낮으면 판정기가 후보 순서에
  흔들린다는 뜻이다.
- **95% 신뢰구간**: 윌슨 구간. 같은 시험을 반복할 때 진짜 정확도가 들어갈 범위로 읽는다.
- **자기 일치율**: 같은 라벨러가 시간을 두고 다시 라벨했을 때 같은 답을 낸 비율.

### 2-4. 합격 규칙 (결과를 보기 전에 정함)

**사람이 두 번 모두 같은 답을 낸 역방향 쌍이 30개 이상이고, 그중 판정기 정확도가 75%
이상이면 합격.** 75%는 사용자가 유지하기로 정했다(10/8). 신뢰구간 상한이 75% 미만이면
쌍 수와 관계없이 불합격으로 본다.

## 3. 1차 시트 (60쌍) — 판정기 불합격, 그리고 라벨 오류

`experiments/label_sheet_20260911.csv`, 라벨 52쌍(8쌍은 애매해서 비움).

| 판정기 | 순방향 | 역방향 | 일관성 |
|---|---|---|---|
| Qwen-7B (라벨 정정 전) | 38쌍 93.9% | 14쌍 30.8% (4/13) | 88.5% |
| Qwen-7B (정정 후) | 41쌍 94.4% | 11쌍 **40.0%** (4/10) | 88.5% |
| Gemma 3 27B (정정 후) | 41쌍 94.9% | 11쌍 **50.0%** (5/10) | 94.2% |

**라벨 오류 3건을 찾아 정정했다.** 판정기가 틀린 역방향 쌍을 직접 읽어 보니 L009(재즈
피아노 쿼리에 오페라 뮤지컬 영화 선택), L041(서점 쿼리에 사전 편찬 영화 선택), L051(미스터리
소설 쿼리에 로맨틱 코미디 영화 선택)은 사람 쪽이 1·2를 바꿔 적은 것으로 보였고, 라벨러가
확인 후 정정했다(`label_sheet_20261008_hyun.csv`).

**구조적 편향**: 역방향 쌍은 "사람이 겹치지 않는 쪽을 골랐다"로 정의되므로, 사람의 실수가
전부 역방향 집합에 몰리고 거기서 판정기가 맞게 골라도 "어휘 추종"으로 집계된다.
**판정기가 틀린 쌍은 반드시 직접 읽어야 한다.** 2차 시트에서 재라벨 단계를 넣은 이유다.

두 판정기가 **같은 4쌍**(L005·L013·L044·L056)에서 똑같이 사람과 반대로 골랐다. L005·L056은
사람이 고른 쪽 설명이 네덜란드어·이탈리아어였고, L044는 "록 음악" 쿼리에 실제 곡(사람)과
록 기타 교본(판정기)이 갈린 — 쿼리가 형식을 요구하는지 내용을 요구하는지의 차이였다.

## 4. 2차 시트 (150쌍) + 재라벨 — 불합격 확정

### 4-1. 시트

`experiments/label_sheet_v2_20261008.csv`. 1차 시트에서 바꾼 것:

- 검색 결과 6개 실행(`eval_lang_ext_*.csv`)을 모두 후보로 썼다(겹치지 않는 새 쌍 최대 835개).
- 1차 시트에 나온 아이템을 모두 뺐다(`--exclude-key`, 겹침 0개 확인).
- 겹침 1개짜리 쌍을 우선했다(`--prefer-ov1 0.7`). 1차 라벨에서 역방향 비율이 겹침 1개 33%
  (27쌍), 2개 0%(18쌍)였기 때문이다. 결과적으로 150쌍 중 124쌍이 겹침 1개다.

1차 라벨: 112쌍 응답, 38쌍 비움. **역방향 37쌍(33%)** — 1차 시트(21%)보다 높다.

### 4-2. 재라벨 (라벨러 1인이라 2인 교차 대신)

역방향 37쌍에 순방향 37쌍을 미끼로 섞고, 좌우를 다시 섞고, 번호를 새로 매겨
(`label_check_v2_20261008.csv`) 같은 라벨러가 다시 라벨했다. 미끼를 섞은 이유는 확인
대상이 역방향뿐이면 "겹치지 않는 쪽이 답"이라고 짐작해 판단이 기울기 때문이다.

| | 자기 일치율 |
|---|---|
| 미끼(순방향) 37쌍 | 34/37 = 91.9% |
| 역방향 37쌍 | 29/35 = 82.9% (2쌍은 재라벨 때 비움) |

재라벨은 1차 약 3시간 뒤에 했다. 기억 때문에 일치율이 부풀었을 수 있으나, 아래 결론은
"두 번 일치한 29쌍"으로 세든 "1차 역방향 37쌍 전체"로 세든 같다.

### 4-3. 판정기 결과 (두 번 일치한 역방향 29쌍)

| 판정기 | 판정 가능 | 정확도 | 95% 신뢰구간 | 순방향 정확도 |
|---|---|---|---|---|
| Qwen-7B | 22 | **54.5%** (12) | 35% ~ 73% | 79.1% |
| Gemma 3 27B | 25 | **36.0%** (9) | 20% ~ 55% | 83.8% |

두 판정기 모두 신뢰구간 상한이 75% 미만이라 **쌍이 29개(<30)여도 불합격이 확정된다.**
더 큰 모델이 더 낫지 않았다 — 1차 시트에서는 Gemma가 한 쌍 앞섰으나 여기서는 뒤집혔다.
이 시트는 겹침 1개짜리 위주라 1차보다 어려워 순방향도 94%대에서 79~84%로 내려갔다.

## 5. 프롬프트 변형 — 효과 없음

모델을 키워도 안 되자 판정 방식을 바꿨다(`judge_pairwise.VARIANTS`,
`score_label_sheet.py --variant`).

- **cot (추론)**: 각 후보가 쿼리의 *뜻*과 어떻게 이어지는지 한두 문장 쓴 뒤 마지막 줄에
  `Answer: N`. 바로 답하면 단어 겹침에 끌려간다는 가설.
- **fewshot (예시)**: 1차 시트의 정답 예시 4개 — 역방향 2(L007, L015) + 순방향 2(L003, L002),
  정답 위치 1·2 반반. 역방향만 넣으면 "겹치지 않는 쪽을 고르라"는 반대 지름길을 배운다.
  1차·2차 시트는 아이템이 겹치지 않지만 **쿼리는 겹친다**(같은 평가 쿼리 40개). 그래서 예시와
  같은 쿼리의 쌍 4개를 뺀 점수도 계산했다.
- **cot_fewshot**: 둘 다.

같은 29쌍 기준:

| 판정기 | 방식 | 역방향 (신뢰구간) | 예시 쿼리 제외 | 순방향 | 일관성 |
|---|---|---|---|---|---|
| Qwen-7B | base | 54.5% (35~73%) | 57.9% | 79.1% | 85% |
| | cot | 41.2% (22~64%) | 38.5% | 87.9% | 72% |
| | fewshot | 40.0% (22~61%) | 38.9% | 87.1% | 78% |
| | cot_fewshot | 53.3% (30~75%) | 53.8% | 91.8% | 62% |
| Gemma 27B | base | 36.0% (20~55%) | 40.9% | 83.8% | 89% |
| | cot | 35.7% (16~61%) | 36.4% | 87.9% | 67% |
| | fewshot | 38.1% (21~59%) | 33.3% | 90.9% | 84% |
| | cot_fewshot | 36.8% (19~59%) | 40.0% | 87.7% | 71% |

- **순방향은 올랐고 역방향은 그대로다.** 단어 겹침과 정답이 같은 방향이면 더 잘 맞히게
  됐지만, 겹치는 쪽이 오답인 경우는 여전히 알아보지 못한다.
- **추론은 일관성을 떨어뜨렸다**(85~89% → 62~72%). 후보 순서만 바꿨는데 답이 바뀌는 경우가
  늘었다. 근거 문장이 먼저 서술한 후보 쪽으로 판단을 끄는 것으로 보인다.
- 추론 출력의 답 읽기 실패는 224건 중 최대 1건이었다(`parse_answer`가 마지막 `Answer: N`을 읽음).

## 6. 결론 및 다음

1. **로컬 판정기(7B·27B, 프롬프트 4종)로는 역방향 쌍을 잡을 수 없다.** 시험한 8개 조합이
   모두 불합격이다. API 판정기는 비용 문제로 쓸 수 없다(10/8 결정).
2. **판정기는 어휘 축과 무관한 실험에만 쓴다.** 순방향 정확도가 80~90%대라, 단어 겹침이
   결과를 좌우하지 않는 실험(4-2 도메인 균형 배치 등)은 기존 방식(base)으로 평가해도 된다.
   변형들은 순방향을 조금 올리는 대신 일관성을 잃어 득실이 분명하지 않다.
3. **4-1처럼 어휘 지름길을 겨냥한 실험은 사람이 직접 평가한다.** 기존 모델과 새 모델의
   결과를 쌍으로 놓고 고르는 방식이며, 이번 라벨 시트 도구를 그대로 쓸 수 있다.
4. **"제목·필드명 제거 증강"(p=0.3, 접음)의 결론은 다시 볼 필요가 있다.** 이 실험도 어휘
   지름길을 줄이려던 것인데 이 판정기로 "효과 없음"을 받았다. 판정기가 그 축을 못 보므로
   결론이 판정기 탓이었을 수 있다.

## 7. 이 과정에서 고친 것 · 알게 된 것

- **판정 캐시 키에 모델 ID가 없었다.** 판정기를 바꿔 돌리면 옛 판정기의 답이 캐시에서
  나와 새 판정기 점수에 섞인다. `pair_cache_path(sig, model_id)`로 고쳤다(기존 Qwen-7B 캐시는
  파일명 유지). 프롬프트 변형도 서명(`prompt_signature(variant)`)으로 분리된다. 절대 등급
  판정(`judge_eval_relevance.py`)의 캐시 키에는 아직 모델 ID가 없다.
- **판정기는 영어로만 평가하면 된다.** 학습은 영어뿐이고 한국어는 서빙의 번역 단계에서만
  개입한다. 한국어 쿼리 결과를 판정할 때는 번역기 출력이 아니라 사람이 쓴 영어 짝
  (`A9_KO` ↔ `A9_EN`)을 판정기에 보여 줘야 번역 오류가 감점된다. 현재
  `judge_pairwise.py --lang ko`는 한국어 원문을 그대로 보여 준다.
- **beast 환경**: 10/1경 대여 측이 Ubuntu 26.04로 올리며 Python 3.12가 사라져 venv 둘 다
  깨졌다. data8tb에 uv로 Python 3.12.15를 설치하고 venv 링크를 돌려 복구했다(원본 백업
  `tools/venv_backup_20261008/`).
- **Mistral Small 3.1 24B (w4a16)**: vLLM 0.26 + transformers 5.14에서 이미지 처리기 시험이
  실패하고, 텍스트 전용 모드로 올리면 의미 없는 문자열을 출력했다. 모델 파일은 삭제했다.
  `--text-only`(이미지 슬롯 0)는 이 모델용이었는데, Gemma 3는 반대로 이 모드에서 기동이
  실패해 옵트인으로 바꿨다.
- **판정기 크기와 속도**: Gemma 27B(w4a16)는 GPU에 16.3GiB로 Qwen-7B(15.7GiB)와 비슷하게
  올라가고, 판정 속도는 약 4배 느리다(초당 11건 대 45건). 실험 1회(약 6,000회 질문) 기준
  10분 남짓이라 속도는 선정 기준이 아니었다.
